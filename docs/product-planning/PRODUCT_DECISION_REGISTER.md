## S2-F. Architecture and data-model classification

How each concept should be treated, per the audit's four-way split:

**Market-neutral (keep as-is):** Workspace, membership and roles; the Lead→Opportunity→Proposal flow; `PipelineStage` (already per-workspace); `DealSide`; `IntentType`; `PropertyPurpose`; `ListingType`; `Activity`/`Task`/`Note`/`Attachment`; `AuditLog`; `AuthSession`/`AccountSetupToken`; the provider interfaces; the idempotency idiom (US-40); the delivery-honesty model (US-38); the fail-closed provider posture (US-44).

**Configurable per workspace:** time zone (US-11, US-12), currency (US-06), locale and date format (US-13), area-unit default (US-09), business hours and quiet hours (not yet modelled, D-14), SLA targets (D-14), AI mode DRAFT/AUTO (US-33, D-11, D-13), assignment strategy (US-29).

**Explicitly market-specific (belongs in a market pack, not core):** lead-source vocabulary (US-23), property-type labels (US-25), the area-unit set (US-09), the language and reply catalogue (US-19), money- and size-word parsing (US-20), AI prompt examples and extraction enums (US-42), seed and demo fixtures (US-21, US-22), activity labels such as site visit versus showing (US-26).

**Canonical storage with locale display:** phone (store E.164, display nationally — US-01), money (store minor units or Decimal plus an explicit currency code, display per locale — US-06, US-07), area (store one canonical unit, display per market — US-10), all timestamps (already UTC in Postgres; the bug is display-side only — US-13), address (structured components, formatted per country — US-16).

**Data-loss and backward-compatibility risks, ranked:**
1. **Phone backfill (US-01).** A blind re-normalization would corrupt existing `+92` rows or re-corrupt already-wrong ones. Any backfill must be region-aware, idempotent, and preceded by a dry-run report. Note that `identity.ts:49-54` deliberately has **no** unique phone index because existing workspaces may already hold duplicates — do not add one without a dedupe pass.
2. **Currency relabelling (US-06).** Changing a column *default* is safe; rewriting existing rows' `currency` would relabel real PKR amounts as USD. Never do the latter.
3. **Enum narrowing (US-09, US-23, US-25).** Postgres cannot drop enum values. Removing `MARLA`, `KANAL`, `ZAMEEN` or `PLOT` would orphan live rows. Additive only, with display-layer labels.
4. **Channel model migration (US-34).** `WhatsAppMessage` holds real conversation history. A new neutral `Conversation`/`Message` pair with a backfill is safe; an in-place rename under load is not.
5. **Response-time backfill (US-37).** Historical leads genuinely lack the data. Reporting must distinguish "no data" from "fast" — inventing a backfill from `lastActivityAt` would fabricate SLA performance.
6. **Baseline migration (carried from Stage 1).** Any existing database still needs `prisma migrate resolve --applied 20260101000000_baseline` once before the next deploy.

## S2-G. Highest-risk findings

1. **No consent infrastructure at all (US-31), and an auto-send path with no consent gate (US-32).** Verified by exhaustive search: zero consent, opt-out, suppression or quiet-hours code exists, while `runConversationTurn()` sends unconditionally. This must be built before any US message is sent. Legal review required.
2. **Speed-to-lead is unmeasurable (US-37).** The product is positioned on accountable speed-to-lead and stores no response timestamps whatsoever. Everything in Stage 4 depends on closing this.
3. **Phone normalization silently corrupts US numbers (US-01 through US-05).** Verified by execution: `415-555-0123` becomes `+4155550123`. It poisons stored identity, duplicate detection (which fails *silently* and completely for US numbers), CSV import, and the live send address.
4. **The AI auto-sends although the decided default is draft (US-33).** D-11 is recorded but not implemented, and there is no mode toggle to turn it off per workspace.
5. **Human takeover does not stop an in-flight AI send (US-36), and there is no `Conversation` entity to hold a control version (US-35).** D-20 has nothing to attach to. This confirms the race as real and unfixed.
6. **WhatsApp-only channel model (US-34).** The US market needs call, text and e-mail; the data model, provider layer, inbox and navigation are all named and shaped around a channel US consumers do not use.
7. **Currency and time zone look configurable but no code can write them (US-12, US-51), while client forms hardcode `currency: "PKR"` (US-50).** A US user creating an opportunity writes PKR today.

**Counterweight — what is already right and should not be rebuilt:** delivery status is honest and ambiguous sends are never retried (US-38); production sending is fail-closed in four explicit states (US-44); DB-level idempotency with advisory locks is established (US-40); provider coupling is genuinely thin (US-46); the AI layer is honest about being deterministic and has prompt-injection defense (US-41); metric single-sourcing is an established pattern (US-54); the fake Google Calendar was removed rather than faked (US-45).
